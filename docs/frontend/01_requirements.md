# 01. 前端需求冻结

## 项目目标

基于现有智慧农业后端与智能体资料，开发一个移动端优先的智慧农业前端管理界面。第一阶段目标不是完整商业系统，而是跑通“登录后查看 A3 实时看板，并能逐步接入地块、设备、灌溉、告警、知识库、AI 会话”的最小闭环。

前端必须复用现有仓库与后端接口设计，不另起一个与项目无关的独立系统。

## 用户角色

- 农户 / 普通用户：查看自己的地块、设备、遥测数据、告警、灌溉状态，并发起手动控制。
- 系统管理员：在普通用户能力基础上，可以维护知识库文档。
- 智能体服务：不是前端用户，但前端需要预留 AI 会话、消息历史和建议采纳入口。

## 核心功能

### 第一优先级

- 登录 / 注册。
- 移动端 A3 实时看板。
- 地块列表与地块详情。
- 最新遥测展示：土壤湿度、环境温度、采样时间。
- 设备在线统计。
- 当前告警数量。
- 灌溉状态展示。
- 手动开启 / 关闭灌溉命令。

### 第二优先级

- 设备列表。
- 设备绑定。
- 阈值规则查看与启停。
- 告警列表。
- 告警确认。
- 命令记录。

### 第三优先级

- 知识库文档列表。
- 管理员上传知识文档。
- AI 会话创建。
- AI 消息历史查看。
- SSE 实时事件展示。

## 非功能要求

- UI 风格参考移动端 A3 实时看板图片：偏白背景、高对比、扁平化、适老化。
- 移动端优先，但桌面端打开时保持居中手机面板形态。
- 页面简洁、实用，不做营销型首页。
- 前端必须按后端已有 `/api/v1` 契约调用接口。
- 数据为空时必须有清晰空状态，不因为后端暂无遥测数据而页面崩溃。
- 交互优先做最小闭环，避免一次性堆完整后台。
- 每个阶段完成后运行本地验证，再进入下一阶段。

## 暂时不做

- 不做大屏驾驶舱。
- 不做复杂地图 GIS。
- 不做完整 AI 流式问答编排。
- 不做数据预测和模型训练页面。
- 不做多租户后台配置。
- 不重构 Go 后端。
- 不改变已存在 API 契约，除非后端文档与代码冲突且必须修正。
