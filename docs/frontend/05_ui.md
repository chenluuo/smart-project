# 05. UI 页面拆分冻结

## 设计目标

前端 UI 采用移动端优先的智慧农业操作台风格。参考图的核心不是装饰，而是信息层级：

- 顶部显示产品名、当前温室/地块、轻量操作入口。
- 第一屏聚焦 A3 实时看板。
- 数据以高对比大数字呈现。
- 卡片边界清晰，背景偏白，绿色表达在线、稳定、可执行。
- 控制按钮大、明确、适合移动端点击。
- 底部固定四项导航，减少页面跳转负担。

## 总体布局

### 桌面端外壳

桌面端不做大屏后台，仍展示移动端应用形态：

```text
页面标题说明
        ↓
居中手机面板
```

桌面端左侧可保留简短标题：

- `移动端 A3 实时看板`
- `偏白背景 · 高对比 · 扁平化 · 适老化`

### 移动端外壳

手机面板内固定结构：

```text
AppHeader
当前页面内容
BottomNav
```

`BottomNav` 固定四项：

| Tab | 页面 | 说明 |
| --- | --- | --- |
| 总览 | `DashboardPage` | 第一优先级页面 |
| 地块 | `PlotListPage` / `PlotDetailPage` | 地块、阈值、遥测 |
| 问答 | `AskPage` | AI 会话与事件 |
| 管理 | `ManagePage` | 设备、告警、知识库、命令 |

## 视觉规范

### 色彩

| 用途 | 建议 |
| --- | --- |
| 页面背景 | `#f5f7f1` / 接近米白的冷白 |
| 卡片背景 | `#ffffff` |
| 主文字 | `#102421` |
| 次文字 | `#64736c` |
| 主要绿色 | `#2f8439` |
| 浅绿色背景 | `#eaf8ee` |
| 警告橙色 | `#cf5d11` |
| 危险红色 | `#cf2727` |
| 边框 | `#dfe8df` |

约束：

- 不做大面积深色背景。
- 不做复杂渐变。
- 不用单一绿色铺满全页面。
- 红色只用于关闭、危险、告警。

### 圆角与边框

- 手机外壳：约 `22px`。
- 页面主卡片：约 `18px`。
- 小卡片与按钮：约 `14px-16px`。
- 边框统一使用浅灰绿。

### 字体层级

| 元素 | 建议 |
| --- | --- |
| 页面大标题 | 28-40px |
| 手机内页面标题 | 22-24px |
| 指标数字 | 30-36px |
| 卡片标题 | 15-18px |
| 辅助说明 | 13-14px |

约束：

- 不使用随视口宽度缩放的字体。
- 按钮文字必须完整显示。
- 移动端优先保证中文不挤压。

### 图标

使用 `lucide-react`：

- 搜索：`Search`
- 通知：`Bell`
- 总览：`Grid2X2`
- 地块：`Map`
- 问答：`MessageSquare`
- 管理：`Settings`
- 湿度：`Droplets`
- 温度：`Thermometer`
- 设备在线：`Wifi`
- 告警：`AlertTriangle`
- 灌溉控制：`Power`

## 页面拆分

## 1. `LoginPage`

### 目标

完成登录 / 注册入口，拿到 Token 后进入 Dashboard。

### 信息结构

```text
标题：智慧农田
副标题：张家湾温室 A3
登录表单：
  - 账号
  - 密码
  - 登录按钮
注册切换：
  - 手机号
  - 账号
  - 密码
```

### 使用 API

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/register`
- `GET /api/v1/users/me`

### 状态

- 加载中。
- 登录失败。
- Token 过期。
- 注册后自动登录。

### 暂不做

- 忘记密码。
- 手机验证码。
- 第三方登录。

## 2. `DashboardPage`

### 目标

实现参考图中的移动端 A3 实时看板，这是第一阶段最小闭环核心。

### 信息结构

```text
页面头：
  智慧农田
  用户名 / 温室 / 当前地块
  搜索、通知、退出/刷新

主卡片：
  A3 地块实时看板
  采样时间
  设备在线数
  在线状态标签
  地块示意图：
    A1 湿度
    A2 湿度
    A3 湿度
    A4 湿度
    中央灌溉核心

指标卡：
  土壤湿度
  环境温度
  设备在线
  当前告警

灌溉控制：
  当前状态
  开启按钮
  关闭按钮
  快捷时长 600 秒 / 900 秒
```

### 使用 API

- `GET /api/v1/dashboard/overview`
- `GET /api/v1/plots`
- `GET /api/v1/plots/{plotId}/telemetry/latest`
- `GET /api/v1/plots/{plotId}/irrigation/status`
- `POST /api/v1/plots/{plotId}/irrigation/commands`
- `GET /api/v1/events/stream`

### 空状态

- 无地块：显示“暂无地块数据”。
- 无遥测：指标显示 `--`，不报错。
- 无灌溉阀门：控制区显示“未绑定灌溉阀门”，按钮禁用。
- 无告警：显示 `0 条 / 暂无告警`。

### 交互

- 点击刷新：重新加载 Dashboard 数据。
- 点击开启：默认 600 秒，带 `Idempotency-Key`。
- 点击关闭：`durationSeconds = 0`。
- 收到 `command.result`：刷新灌溉状态和命令。
- 收到 `alert.created`：刷新告警数量。

## 3. `PlotListPage`

### 目标

查看当前用户地块列表，选择地块进入详情。

### 信息结构

```text
标题：地块
地块列表：
  - 地块名称
  - 地块编号
  - 作物
  - 状态
  - 最新湿度 / 温度摘要
```

### 使用 API

- `GET /api/v1/plots`
- `GET /api/v1/dashboard/overview`

### 交互

- 点击地块：进入 `PlotDetailPage` 或在当前页展开详情。

## 4. `PlotDetailPage`

### 目标

展示单个地块详情、最新遥测、来源设备、阈值规则。

### 信息结构

```text
地块基础信息：
  - 编号
  - 名称
  - 作物
  - 面积
  - 状态

遥测：
  - 土壤湿度
  - 温度
  - 采样时间

来源设备：
  - 设备名称
  - 状态
  - 电量

阈值规则：
  - 指标
  - 操作符
  - 阈值
  - 持续时间
  - 启用状态
```

### 使用 API

- `GET /api/v1/plots/{plotId}`
- `GET /api/v1/plots/{plotId}/telemetry/latest`
- `GET /api/v1/plots/{plotId}/thresholds`
- `PUT /api/v1/plots/{plotId}/thresholds/{thresholdId}`

### 交互

- 启用 / 停用阈值规则。
- 第一阶段不做复杂阈值编辑表单；如要编辑，只做最小字段。

## 5. `DeviceListPage`

### 目标

展示设备列表，并支持按地块、状态、类型筛选。

### 信息结构

```text
筛选区：
  - 地块
  - 状态
  - 类型

设备列表：
  - 设备名称
  - SN
  - 类型
  - 在线状态
  - 电量
  - 最后心跳
```

### 使用 API

- `GET /api/v1/devices`
- `GET /api/v1/plots`

### 交互

- 点击设备进入 `DeviceDetailPage`。
- 分页先使用“加载更多”或简单上一页/下一页，不做复杂分页器。

## 6. `DeviceDetailPage`

### 目标

展示单个设备状态详情。

### 信息结构

```text
设备状态：
  - 状态
  - 电量
  - 信号
  - 最后心跳
  - 状态说明
```

### 使用 API

- `GET /api/v1/devices/{deviceId}/status`

### 暂不做

- 设备固件升级。
- 设备凭据管理。

## 7. `ControlPanelPage`

### 目标

集中管理灌溉控制和命令记录。

### 信息结构

```text
当前地块选择
灌溉状态卡
控制按钮：
  - 开启 600 秒
  - 开启 900 秒
  - 自定义时长
  - 关闭
命令记录：
  - commandId
  - 地块
  - 动作
  - 状态
  - 发起时间
```

### 使用 API

- `GET /api/v1/plots/{plotId}/irrigation/status`
- `POST /api/v1/plots/{plotId}/irrigation/commands`
- `GET /api/v1/commands`
- `GET /api/v1/commands/{commandId}`

### 交互约束

- 开启时长必须在 60 到 1800 秒。
- 关闭命令必须传 `durationSeconds = 0`。
- 每次控制必须生成新的 `Idempotency-Key`。

## 8. `AlarmCenterPage`

### 目标

展示告警列表和处理动作。

### 信息结构

```text
筛选：
  - 地块
  - 状态

告警列表：
  - 标题
  - 内容
  - 级别
  - 当前值
  - 阈值
  - 触发时间
  - 状态
  - 确认按钮
```

### 使用 API

- `GET /api/v1/alerts`
- `GET /api/v1/alerts/logs`
- `POST /api/v1/alerts/{alertId}/confirm`

### 交互

- 活动告警显示确认按钮。
- 确认时必须输入 `remark`。
- 确认后刷新列表。

## 9. `AskPage`

### 目标

预留 AI 会话入口，不在第一阶段实现完整流式问答。

### 信息结构

```text
当前地块
新建会话按钮
会话摘要
消息历史
最近实时事件
```

### 使用 API

- `POST /api/v1/ai/sessions`
- `GET /api/v1/ai/sessions/{sessionId}/messages`
- `POST /api/v1/ai/sessions/{sessionId}/close`
- `GET /api/v1/events/stream`

### 暂不做

- 完整 `POST /agent/chat` 流式问答。
- AI 建议采纳。
- 工具调用链路可视化。

## 10. `KnowledgePage`

### 目标

展示知识文档列表，管理员可上传。

### 信息结构

```text
分类筛选
文档列表：
  - 标题
  - 分类
  - 版本
  - 来源
  - 更新时间
  - 下载入口

管理员上传：
  - 文件
  - 标题
  - 分类
  - 来源
  - 版本
```

### 使用 API

- `GET /api/v1/knowledge/docs`
- `POST /api/v1/knowledge/docs`
- `POST /api/v1/knowledge/docs/{docId}/approve`
- `POST /api/v1/knowledge/docs/{docId}/publish`
- `POST /api/v1/knowledge/docs/{docId}/archive`

### 阶段边界

第一阶段只做：

- 文档列表。
- 管理员上传。

审核、发布、归档可以作为后续管理能力。

## 11. `ManagePage`

### 目标

第一阶段用作移动端管理入口，整合二级能力，避免底部导航过多。

### 包含入口

- 设备列表。
- 设备绑定。
- 告警中心。
- 命令记录。
- 知识库。

### 使用方式

第一阶段可以先在一个 `ManagePage` 中用卡片分区承载这些功能。后续功能增多后，再拆成独立页面。

## 开发顺序

按最小闭环推进，不一次性完成全部页面。

1. `LoginPage`
2. `DashboardPage`
3. `PlotListPage`
4. `PlotDetailPage`
5. `DeviceListPage`
6. `DeviceDetailPage`
7. `ControlPanelPage`
8. `AlarmCenterPage`
9. `AskPage`
10. `KnowledgePage`
11. `ManagePage` 整理入口

当前已有的 `App.tsx` 可以作为初始雏形。进入开发阶段后，按顺序逐步拆分，不做一次性大重构。

## 验收标准

### UI 验收

- 手机面板居中显示。
- 第一屏能看到 A3 实时看板。
- 指标数字清晰，移动端不拥挤。
- 底部导航固定、可点击、状态明显。
- 灌溉开启和关闭按钮足够醒目。
- 空数据时页面仍然完整。

### 功能验收

- 未登录时只显示登录 / 注册。
- 登录成功后进入 Dashboard。
- Dashboard 至少能调用：
  - `/api/v1/users/me`
  - `/api/v1/plots`
  - `/api/v1/dashboard/overview`
- 无后端数据时不崩溃。
- 灌溉控制失败时给出明确错误提示。

### 阶段验收

每完成一个页面模块：

- 运行构建。
- 手动打开页面检查布局。
- 更新 `06_tasks.md`。
- 只提交当前模块相关变更。
