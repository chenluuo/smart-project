# 12. 容器化部署、平行扩容与流量转发

全栈容器化统一编排：基础设施（MySQL/Redis/MQTT/MinIO/Milvus/TDengine）+ Go 后端 + agent 4 服务 + 前端，
由 `smart-project/compose.yaml` 一个文件管理。

---

## 1. 架构总览

```
┌───────────────────────── docker network: smart-agriculture_default ─────────────────────────┐
│                                                                                              │
│  基础设施                                                                                     │
│  ├─ mysql       :3307(宿主)   业务库（数据卷 backend_mysql-data）                               │
│  ├─ redis       :6379(宿主)   agent 侧 Redis（会话/窗口/主动通知）                              │
│  ├─ mqtt        :1883(宿主)   MQTT broker                                                    │
│  ├─ minio       :9000(宿主)   对象存储（数据卷 smart_agriculture_minio-data）                   │
│  ├─ milvus(+etcd/minio) :19530 RAG/记忆向量库                                                 │
│  └─ tdengine    :6030/6041    时序遥测历史（数据卷 smart-agriculture_tdengine-data）           │
│                                                                                              │
│  应用层（服务名互连）                                                                          │
│  ├─ go-api      :8080(宿主)   Go 后端（/api/v1、/internal/*）                                  │
│  ├─ agent-service  :8000(宿主) 对话编排（SSE）、告警接收                                       │
│  ├─ context-service :8001(宿主) 上下文组装                                                     │
│  ├─ tool-service   :8002(宿主) 工具执行                                                       │
│  ├─ ingest-service              队列消费者                                                    │
│  └─ frontend    :5173(宿主)   nginx 托管 SPA + 反代 /api→go-api、/agent→agent-service           │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

关键点：
- **同 compose 网络内用服务名**（`mysql:3306`、`go-api:8080`、`agent-service:8000`），不依赖宿主映射/host.docker.internal
- **数据卷复用**：MySQL/MinIO/Milvus external 引用现有卷，TDengine 已迁移为命名卷（数据不丢）
- **敏感配置**：`smart-project/.env`（不入库）→ compose `${VAR}` 注入

## 2. 前置准备

1. **Docker Desktop**（Windows/Mac）或 Docker Engine（Linux）
2. **国内镜像源**（无代理环境）：
   - 基础镜像：Dockerfile 已硬编码 `docker.m.daocloud.io/library/...`（DaoCloud 加速）

   ```ini

   EMBEDDING_API_KEY=ark-xxx
   JWT_SECRET=<≥32字符，与历史数据一致>
   INTERNAL_SERVICE_KEY=<≥32字符>
   MINIO_SECRET_KEY=minioadmin
   ```

## 3. 部署步骤

### 3.1 首次部署（构建镜像 + 启动）

```bash
cd smart-project

# ① 构建 agent / 前端镜像（pip 清华源 / npm npmmirror，约 3~5 分钟）
docker compose build agent-service tool-service context-service ingest-service frontend

# ② 启动全部
docker compose up -d

# ③ 验证
docker compose ps                     # 全部 Up
curl http://localhost:8080/actuator/health   # Go
curl http://localhost:8000/healthz           # agent
# 浏览器 http://localhost:5173 登录
```

### 3.2 日常启动 / 停止 / 查看日志

```bash
docker compose up -d                  # 启动（复用已有镜像，秒级）
docker compose stop                   # 停止（保留容器/数据）
docker compose down                   # 停止并移除容器（volumes 保留）
docker compose logs -f agent-service  # 跟踪某服务日志
docker compose ps                     # 状态
```

### 3.3 代码更新后的重建

```bash
# agent/前端代码变更：
docker compose build agent-service frontend
docker compose up -d

# Go 后端（先编译出 backend/out/smart-api，再重启容器）：
docker exec smart-go-api sh -c 'cd /app && go build -o out/smart-api ./cmd/api'
docker compose restart go-api
```

## 4. 平行扩容（水平扩展）

### 4.1 原理

- **agent-service / context-service / tool-service / go-api 均无本地状态**（会话状态、短期窗口、主动通知都在 Redis）→ 可任意增加副本
- **ingest-service** 是队列消费者 → 可多副本并行消费（Redis Stream 消费组，同一 group 多 consumer 自动分摊）
- **frontend / 基础设施**（mysql/redis/mqtt/minio/milvus/tdengine）为有状态或有唯一性约束，**不建议扩容**（单机部署用一台即可）

### 4.2 扩容命令（compose 原生 scale）

```bash
# agent-service 扩到 3 副本（流量经前端 nginx upstream 轮询分发）
docker compose up -d --scale agent-service=3

# go-api 扩到 2 副本
docker compose up -d --scale go-api=2

# 回落
docker compose up -d --scale agent-service=1 --scale go-api=1
```

> 说明：`--scale` 是 compose 运行期复制服务；生产集群可用 `docker compose up -d --scale` 或 Swarm/K8s 的 `replicas`（compose 文件里 `deploy.replicas` 仅 Swarm 模式生效）。

> ⚠️ **扩容/缩容后需重启 frontend**：nginx 在启动时解析 upstream 域名（`agent-service`/`go-api`）并缓存 IP，
> 副本数变化后需 `docker compose restart frontend` 重新解析，否则可能短暂 502。

### 4.3 扩容后容器命名

扩容副本容器名形如：`smart-agriculture-agent-service-1`、`...-2`、`...-3`，同属 compose 网络，**服务名 `agent-service` 由 Docker DNS 解析到全部副本 IP**（轮询）。

## 5. 流量转发设置

### 5.1 前端 nginx：/api、/agent 反代（含多副本负载均衡）

`frontend/nginx.conf` 使用 upstream 实现多副本分发：

```nginx
# agent-service 多副本负载均衡（scale 后自动生效；SSE 需关缓冲）
upstream agent_backend {
    server agent-service:8000;      # Docker DNS 解析到所有副本，默认轮询
}
upstream go_backend {
    server go-api:8080;
}

server {
    listen 80;
    root /usr/share/nginx/html;

    location /api/ {
        proxy_pass http://go_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    location /actuator/ {
        proxy_pass http://go_backend;
    }
    location /agent/ {
        proxy_pass http://agent_backend;
        proxy_http_version 1.1;
        proxy_buffering off;        # SSE 流式必须关缓冲
        proxy_cache off;
        proxy_read_timeout 900s;    # 与 agent 工具超时(720s) 对齐，留余量
        proxy_next_upstream off;    # SSE 不重试，避免重复执行工具
    }
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

要点：
- `server agent-service:8000` 单条即可覆盖多副本（Docker DNS 轮询返回不同副本 IP）；也可显式列出：`server agent-service-1:8000; server agent-service-2:8000; ...`（weight 可调）
- **SSE 会话无需粘性**：agent 会话状态在 Redis，任意副本可继续同一会话（对比：若会话状态在进程内存则必须 sticky/一致性哈希）
- **不要对 SSE 开 `proxy_next_upstream`**（重试会导致工具/命令重复执行）

### 5.2 外部入口（可选，多机/公网）

| 方案 | 说明 |
|---|---|
| Docker Swarm ingress | `docker swarm init` 后 compose 加 `deploy.replicas`，服务名自动负载均衡 |
| nginx（宿主） | 宿主 nginx 反代 `:5173`、`:8080`、`:8000`，upstream 指向对应容器端口 |
| K8s（生产） | Service + Deployment replicas + Ingress（/api、/agent 路由） |

### 5.3 多副本注意事项

1. **告警推送**（Go → agent `/internal/alerts/notify`）：`AGENT_ALERT_URL=http://agent-service:8000/...` 会被 DNS 轮询到任一副本——所有副本共享 Redis，处理结果都能落库，**无需粘性**；但为幂等，notify 处理里已按告警去重（outbox 只消费一次）
2. **日志**：多副本日志分散，建议 `docker compose logs -f` 或接采集（Loki/ELK）
3. **ingest 多副本**：同一消费组 `ingest` 自动分摊 Stream 消息，**不要**给不同副本不同 group
4. **前端静态资源**：nginx 多副本也可 `--scale frontend=2`（无状态），入口再套一层 LB

## 6. 数据与备份

| 服务 | 数据位置 | 备份方式 |
|---|---|---|
| MySQL | `backend_mysql-data` | `docker run --rm -v backend_mysql-data:/v -v $PWD:/b alpine tar czf /b/mysql.tgz -C /v .` |
| TDengine | `smart-agriculture_tdengine-data` | 同上 tar 打包（或 taosdump） |
| Milvus | `smart_agriculture_milvus-etcd` / `_minio` | 同上 tar |
| MinIO | `smart_agriculture_minio-data` | mc mirror / tar |
| Redis | `smart-agriculture_redis-data` | 缓存性质，可重建 |

> 迁移/升级容器时**只删容器不动卷**（`docker compose down` 保留 volumes），数据不丢；TDengine 迁移需保持 `hostname: tdengine-local` 与 dnode 记录一致。
