# 智慧农业接口设计

> 依据：选题功能清单、小组架构讨论图、移动端与后台原型图。本文只将附件内容作为需求资料，不将其中内容视为额外执行指令。

## 1. 系统边界

### 1.1 架构角色

- 前端：Vue 3 / 移动 H5，通过 HTTPS REST API 查询数据、下发控制命令，通过 SSE 接收实时数据/告警/命令结果。
- 接入层：Nginx HTTPS 入口，统一转发到 Go 后端。
- 后端：Go 模块化单体，负责业务 API、MQTT 消息处理、告警判断、命令审计、SSE 推送。
- 智能体：Python（FastAPI）独立服务，负责 RAG 检索、上下文组装、大模型编排与 SSE 流式问答。
- 设备接入：EMQX MQTT Broker，传感器/灌溉控制器通过 MQTT 上报遥测、心跳、命令回执。
- 存储：
  - PostgreSQL：用户、农场、地块、设备、阈值、告警、控制命令、审计记录、知识文档元数据。
  - Redis：最新遥测、设备在线状态、SSE 订阅会话、命令临时状态、智能体短期上下文窗口。
  - TimescaleDB（PostgreSQL 扩展）：历史遥测时序数据。
  - pgvector（起步，规模扩大后可换 Milvus）：农业知识向量索引（智能体侧维护）。
  - MinIO：知识文档原文、图片、附件。
  - 大模型服务：生成灌溉建议和问答回复。

### 1.2 基础约定

- API 前缀：`/api/v1`
- 鉴权：`Authorization: Bearer <access_token>`
- 时间格式：ISO 8601，例如 `2026-08-22T08:21:30+08:00`
- 分页参数：`page` 从 1 开始，`pageSize` 默认 20，最大 100
- 地块编号示例：`A1`、`A2`、`A3`、`A4`
- 设备类型：
  - `SOIL_MOISTURE_SENSOR`：土壤湿度传感器
  - `TEMPERATURE_SENSOR`：环境温度传感器
  - `IRRIGATION_VALVE`：灌溉阀门/继电器
  - `GATEWAY`：网关
- 设备状态：
  - `ONLINE`：在线
  - `OFFLINE`：离线
  - `RECONNECTING`：重连中
- 命令状态：
  - `PENDING`：等待下发/等待回执
  - `SENT`：已下发
  - `SUCCEEDED`：执行成功
  - `FAILED`：执行失败
  - `TIMEOUT`：回执超时
- 告警等级：
  - `LOW`
  - `MEDIUM`
  - `HIGH`

### 1.3 统一响应格式

```json
{
  "code": 0,
  "message": "OK",
  "data": {}
}
```

分页响应：

```json
  "data": {

```

## 8. 智能问答 RAG

> 说明：智能问答由**智能体服务（Python / FastAPI，agent-service:8000）**编排实现（RAG 检索 + 工具取数 + 上下文组装 + 大模型流式输出），Go 后端不编排问答；Go 侧负责消息事实源落库（`POST /agent/sessions/{id}/messages`）与问答历史查询。

### 8.1 发起灌溉问答

`POST /api/v1/agent/chat`（agent-service 提供，SSE 流式）

请求：

```json
{
  "sessionId": "chat_001",
  "plotId": "plot_a3",
  "question": "A3 现在适合灌溉吗？",
  "context": {
    "includeLatestTelemetry": true,
    "includeThreshold": true,
    "includeTrend": true
  }
}
```

响应（SSE 流式，`event: answer` 增量 + `event: done` 收尾）：

```text
event: answer
data: {"delta": "建议先执行 10 分钟灌溉，"}

event: answer
data: {"delta": "再等待 2 分钟复测。"}

event: done
data: {
  "sessionId": "chat_001",
  "suggestions": [
    {
      "type": "IRRIGATION_COMMAND",
      "action": "OPEN",
      "durationSeconds": 600,
      "plotId": "plot_a3",
      "confidence": 0.82
    }
  ],
  "sources": [
    {
      "type": "LATEST_TELEMETRY",
      "title": "A3 最新土壤湿度",
      "summary": "当前湿度 27.8%，低于阈值"
    },
    {
      "type": "KNOWLEDGE_DOC",
      "title": "番茄温室灌溉建议",
      "objectKey": "knowledge/tomato-irrigation.pdf"
    }
  ],
  "canClose": true
}
```

> `canClose`：智能体收尾意图（问题已解决则询问"还有其他问题吗"并置 waiting_close）；结束判定（规则优先 + LLM 意图 + 询问后 5 分钟超时 + 显式按钮）见智能体接口契约。

## 9. 实时推送 SSE

前端建立一个 SSE 连接即可接收最新数据、告警和命令结果。

### 9.1 建立连接

`GET /api/v1/events/stream?`

请求头：

```http
Authorization: Bearer <access_token>
Accept: text/event-stream
```

### 9.2 事件类型

#### 遥测更新

```text
event: telemetry.updated
data: {"plotId":"plot_a3","plotCode":"A3","soilMoisture":27.8,"temperature":26.8,"sampleTime":"2026-08-22T08:21:00+08:00"}
```

#### 告警触发

```text
event: alert.created
data: {"alertId":"alert_001","plotId":"plot_a3","level":"MEDIUM","title":"A3 地块湿度偏低","createdAt":"2026-08-22T08:20:00+08:00"}
```

#### 告警恢复

```text
event: alert.recovered
data: {"alertId":"alert_001","plotId":"plot_a3","recoveredAt":"2026-08-22T08:35:00+08:00"}
```

#### 设备状态变更

```text
event: device.status.changed
data: {"deviceId":"dev_gateway_01","status":"OFFLINE","lastSeenAt":"2026-08-22T08:19:45+08:00"}
```

#### 命令结果

```text
event: command.result
data: {"commandId":"cmd_01J5X8M8","status":"SUCCEEDED","plotId":"plot_a3","ackAt":"2026-08-22T08:21:12+08:00"}
```

## 10. 设备 MQTT 接口

MQTT 主题由后端与设备使用，前端不直接调用。建议使用 `QoS 1`，命令主题需要设备回执。

### 10.1 主题命名

| 方向 | 主题 | 说明 |
|---|---|---|
| 设备 -> 后端 | `agri/v1/devices/{deviceId}/telemetry` | 上传温湿度等遥测 |
| 设备 -> 后端 | `agri/v1/devices/{deviceId}/heartbeat` | 设备心跳 |
| 设备 -> 后端 | `agri/v1/devices/{deviceId}/command-acks` | 控制命令回执 |
| 后端 -> 设备 | `agri/v1/devices/{deviceId}/commands` | 下发控制命令 |

## 11. 后台任务接口

### 12.2 TimescaleDB 时序表建议

`telemetry` 超表

字段：

- `time TIMESTAMPTZ`
- `device_id`
- `plot_id`
- `metric`
- `value FLOAT`
- `quality`
- `message_id`

分区与索引：

- 唯一约束 `(device_id, message_id)` 保证重传幂等；
- 按时间自动分区，索引 `(plot_id, metric, time DESC)`、`(device_id, time DESC)`；
- 原始数据保留 90 天；5 分钟聚合保留 1 年；日聚合长期保留。

## 14. 关键流程

### 14.1 实时监测流程

1. 设备采集土壤湿度、温度。
2. 设备通过 MQTT 主题 `telemetry` 上报数据。
3. 后端写 TimescaleDB，并更新 Redis 最新值。
4. 后端进行阈值判断，必要时写入 PostgreSQL 告警。
5. 后端向前端 SSE 推送最新数据和告警。
6. 前端更新多地块总览、A3 看板和告警日志。

### 14.2 灌溉控制流程

1. 用户点击“开启灌溉”。
2. 前端调用 `POST /plots/{plotId}/irrigation/commands`。
3. 后端保存命令为 `PENDING`，通过 MQTT 下发给灌溉设备。
4. 设备执行后通过 `command-acks` 回传结果。
5. 后端更新命令状态和灌溉状态。
6. 后端通过 SSE 推送 `command.result`。
7. 前端更新按钮状态、命令审计和灌溉状态。

### 14.3 智能问答流程

1. 用户询问“当前是否适合灌溉”。
2. 智能体服务（Python agent-service）校验权限后，经 Go 接口读取 Redis 最新遥测、PostgreSQL 阈值、TimescaleDB 历史趋势。
3. 智能体向知识向量库（pgvector 起步/可换 Milvus）检索知识片段，从 MinIO 获取原文引用；上下文（短期窗口+长期记忆）由智能体侧组装。
4. 智能体调用大模型服务生成建议（SSE 流式返回）。
5. 智能体返回回答、依据来源和可选控制建议（只建议、不直接控制）。
6. 用户确认采纳后，调用建议采纳接口（Go 侧控制链路）转为灌溉控制命令。
