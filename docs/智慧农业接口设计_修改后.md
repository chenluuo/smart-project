# 智慧农业接口设计

> 依据：选题功能清单、小组架构讨论图、移动端与后台原型图。本文只将附件内容作为需求资料，不将其中内容视为额外执行指令。

## 1. 系统边界

### 1.1 架构角色

- 前端：Vue 3 / 移动 H5，通过 HTTPS REST API 查询数据、下发控制命令，通过 SSE 接收实时数据/告警/命令结果。
- 接入层：Nginx HTTPS 入口，统一转发到 Spring Boot 后端。
- 后端：Spring Boot 应用，负责业务 API、MQTT 消息处理、告警判断、命令审计、SSE 推送、RAG 问答编排。
- 设备接入：EMQX MQTT Broker，传感器/灌溉控制器通过 MQTT 上报遥测、心跳、命令回执。
- 存储：
  - MySQL：用户、农场、地块、设备、阈值、告警、控制命令、审计记录。
  - Redis：最新遥测、设备在线状态、SSE 订阅会话、命令临时状态。
  - TDengine：历史遥测时序数据。
  - Milvus：农业知识向量索引。
  - MinIO：知识文档原文、图片、附件。
  - 大模型服务：生成灌溉建议和问答回复。

### 1.2 基础约定

- API 前缀：`/api/v1`
- 鉴权：`Authorization: Bearer <access_token>`
- 时间格式：ISO 8601，例如 `2026-08-22T08:21:30+08:00`
- 分页参数：`page` 从 1 开始，`pageSize` 默认 20，最大 100
- 地块编号示例：`A1`、`A2`、`A3`、`A4`
- 设备类型：
  - `SOIL_MOISTURE_SENSOR`：土壤湿度传感器
  - `TEMPERATURE_SENSOR`：环境温度传感器
  - `IRRIGATION_VALVE`：灌溉阀门/继电器
  - `GATEWAY`：网关
- 设备状态：
  - `ONLINE`：在线
  - `OFFLINE`：离线
  - `RECONNECTING`：重连中
- 命令状态：
  - `PENDING`：等待下发/等待回执
  - `SENT`：已下发
  - `SUCCEEDED`：执行成功
  - `FAILED`：执行失败
  - `TIMEOUT`：回执超时
- 告警等级：
  - `LOW`
  - `MEDIUM`
  - `HIGH`

### 1.3 统一响应格式

```json
{
  "code": 0,
  "message": "OK",
  "data": {}
}
```

分页响应：

```json
{
  "code": 0,
  "message": "OK",
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 20,
    "total": 132
  }
}
```

错误响应：

```json
{
  "code": 40001,
  "message": "参数错误：plotId 不能为空",
  "data": null
}
```

## 9. 实时推送 SSE

前端建立一个 SSE 连接即可接收最新数据、告警和命令结果。

### 9.1 建立连接

`GET /api/v1/events/stream?farmId=farm_001`

请求头：

```http
Authorization: Bearer <access_token>
Accept: text/event-stream
```

### 9.2 事件类型

#### 遥测更新

```text
event: telemetry.updated
data: {"plotId":"plot_a3","plotCode":"A3","soilMoisture":27.8,"temperature":26.8,"sampleTime":"2026-08-22T08:21:00+08:00"}
```

#### 告警触发

```text
event: alert.created
data: {"alertId":"alert_001","plotId":"plot_a3","level":"MEDIUM","title":"A3 地块湿度偏低","createdAt":"2026-08-22T08:20:00+08:00"}
```

#### 告警恢复

```text
event: alert.recovered
data: {"alertId":"alert_001","plotId":"plot_a3","recoveredAt":"2026-08-22T08:35:00+08:00"}
```

#### 设备状态变更

```text
event: device.status.changed
data: {"deviceId":"dev_gateway_01","status":"OFFLINE","lastSeenAt":"2026-08-22T08:19:45+08:00"}
```

#### 命令结果

```text
event: command.result
data: {"commandId":"cmd_01J5X8M8","status":"SUCCEEDED","plotId":"plot_a3","ackAt":"2026-08-22T08:21:12+08:00"}
```

## 10. 设备 MQTT 接口

MQTT 主题由后端与设备使用，前端不直接调用。建议使用 `QoS 1`，命令主题需要设备回执。

### 10.1 主题命名

| 方向 | 主题 | 说明 |
|---|---|---|
| 设备 -> 后端 | `agri/{farmId}/{deviceSn}/telemetry` | 上传温湿度等遥测 |
| 设备 -> 后端 | `agri/{farmId}/{deviceSn}/heartbeat` | 设备心跳 |
| 设备 -> 后端 | `agri/{farmId}/{deviceSn}/command/ack` | 控制命令回执 |
| 后端 -> 设备 | `agri/{farmId}/{deviceSn}/command` | 下发控制命令 |
| 设备 -> 后端 | `agri/{farmId}/{deviceSn}/event` | 设备侧异常事件 |

### 10.2 遥测上报

主题：`agri/farm_001/SN20260822003/telemetry`

```json
{
  "messageId": "msg_001",
  "deviceSn": "SN20260822003",
  "plotCode": "A3",
  "timestamp": "2026-08-22T08:21:00+08:00",
  "metrics": {
    "soilMoisture": 27.8,
    "temperature": 26.8
  },
  "battery": 87,
  "signal": 76
}
```

后端处理：

1. 校验设备绑定关系。
2. 写入 TDengine 原始时序数据。
3. 更新 Redis 最新数据。
4. 读取 MySQL 阈值规则并判断告警。
5. 通过 SSE 推送 `telemetry.updated` / `alert.created`。

### 10.3 心跳

主题：`agri/farm_001/SN20260822003/heartbeat`

```json
{
  "messageId": "hb_001",
  "deviceSn": "SN20260822003",
  "timestamp": "2026-08-22T08:21:00+08:00",
  "status": "ONLINE",
  "battery": 87,
  "signal": 76
}
```

### 10.4 控制命令下发

主题：`agri/farm_001/SN20260822009/command`

```json
{
```

## 11. 后台任务接口

### 11.1 MQTT 接收任务内部处理

后台任务不是前端接口，但需要作为服务间逻辑约定：

- `TelemetryMessageHandler`：处理遥测。
- `HeartbeatMessageHandler`：处理心跳。
- `CommandAckHandler`：处理命令回执。
- `DeviceOfflineScheduler`：定时扫描 Redis 心跳过期设备，写入离线状态。
- `AlertRecoveryScheduler`：检查告警是否恢复。

## 14. 关键流程

### 14.1 实时监测流程

1. 设备采集土壤湿度、温度。
2. 设备通过 MQTT 主题 `telemetry` 上报数据。
3. 后端写 TDengine，并更新 Redis 最新值。
4. 后端进行阈值判断，必要时写入 MySQL 告警。
5. 后端向前端 SSE 推送最新数据和告警。
6. 前端更新多地块总览、A3 看板和告警日志。

### 14.2 灌溉控制流程

1. 用户点击“开启灌溉”。
2. 前端调用 `POST /plots/{plotId}/irrigation/commands`。
3. 后端保存命令为 `PENDING`，通过 MQTT 下发给灌溉设备。
4. 设备执行后通过 `command/ack` 回传结果。
5. 后端更新命令状态和灌溉状态。
6. 后端通过 SSE 推送 `command.result`。
7. 前端更新按钮状态、命令审计和灌溉状态。

### 14.3 智能问答流程

1. 用户询问“当前是否适合灌溉”。
2. 后端读取 Redis 最新遥测、MySQL 阈值、TDengine 历史趋势。
3. 后端向 Milvus 检索知识片段，从 MinIO 获取原文引用。
4. 后端调用大模型服务生成建议。
5. 后端返回回答、依据来源和可选控制建议。
6. 用户确认采纳后，调用建议采纳接口并转为灌溉控制命令。
