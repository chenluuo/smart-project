# 二阶段仓储模块后端任务清单

> 范围：数据库、Go 后端、仓储 API、权限、事务并发和后端测试。
> 不包含：前端、采购意向完整状态机、Agent 侧实现。
> 核心规则：全链路无价格字段；库存变化必须有流水；成交扣库必须防超卖。

> 实际状态（2026-08-30）：仓储数据库、Go 领域模型、Repository、Service、HTTP API、权限、幂等入库、订单扣库能力、outbox 和核心测试已经实现并提交。仓储域目前仅 `WAREHOUSE_MANAGER / SYSTEM_ADMIN` 可访问；`FARMER / FARM_ADMIN / TECHNICIAN / CUSTOMER` 均不能查询或写入仓储数据。采购意向/订单模块尚未接入，生产装配使用 `NoReservations`，所以当前占用量为 `0`。

## 一、确认仓储边界

- [ ] 仓储模块负责物料、仓库、实物库存和出入库流水。
- [ ] 订单模块负责 `TRADING` 状态订单的虚拟占用。
- [ ] 确认可售数量公式：`available = total stock - TRADING order items`。
- [ ] 仓储模块提供锁定和扣减库存能力，不直接修改订单状态。
- [ ] 成交由交易 service 统一编排订单更新、库存扣减和 OUT 流水，并在同一事务提交。

# 仓储模块实现文档

> 本章描述当前 Go 后端的实际实现，而不是未来方案。对应代码位于：
>
> - `backend/internal/trade/warehouse_model.go`
> - `backend/internal/trade/warehouse_repository.go`
> - `backend/internal/trade/warehouse_service.go`
> - `backend/internal/http/warehouse.go`
> - `backend/internal/platform/database/migrations/015_create_warehouse_schema.sql`
>
> 当前实现范围是仓储主数据、实物库存、出入库流水、收获入库、订单扣库能力和仓储 HTTP API。采购意向/订单模块尚未接入，因此生产装配暂时使用 `NoReservations`，当前 `reservedQuantity` 为 `0`；订单模块完成后只需注入 `ReservationReader` 的真实实现。

## 十六、模块分层与调用关系

```text
HTTP Handler
  ├─ 解析 JWT、路径、查询参数、JSON、Idempotency-Key
  ├─ 执行角色校验
  └─ 调用 WarehouseService
        ├─ 执行业务校验、定点数量计算、幂等判断
        ├─ 编排数据库事务
        ├─ 调用 ReservationReader 读取 TRADING 占用
        └─ 调用 Repository
              ├─ 主数据 CRUD 和软删除
              ├─ SELECT ... FOR UPDATE
              ├─ 原子增减库存
              ├─ 写入不可变库存流水
              └─ 写入 outbox_events
```

模块职责：

- Handler 只处理 HTTP 协议，不允许客户端传入 `operatorId`。
- Service 负责校验、幂等、事务和跨 Repository 编排。
- Repository 负责 SQL/GORM、锁、原子更新和错误归一化。
- `ReservationReader` 是仓储与订单模块之间的依赖倒置边界。
- 所有库存运算使用 `shopspring/decimal`，不使用 `float32/float64`。

## 十七、统一 HTTP 协议

### 17.1 基础信息

- API 前缀：`/api/v1`
- 鉴权方式：`Authorization: Bearer <JWT>`
- 请求与响应类型：`application/json`
- 时间格式：RFC 3339，例如 `2026-08-30T10:30:00Z`
- 数量精度：最多 3 位小数，建议 JSON 中使用字符串，例如 `"500.125"`
- 分页默认值：`page=1&pageSize=20`
- `pageSize` 合法范围：`1～100`

### 17.2 成功响应

所有接口使用统一响应包装：

```json
{
  "code": 0,
  "message": "OK",
  "data": {}
}
```

分页响应的 `data` 格式：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0
}
```

### 17.3 失败响应

```json
{
  "code": 40001,
  "message": "参数错误",
  "data": null
}
```

当前仓储接口错误映射：

| HTTP 状态 | code | 场景 |
|---|---:|---|
| 400 | 40001 | 非法 ID、分页、状态、时间、数量、JSON 或缺少幂等键 |
| 401 | 40101 | 未携带 JWT 或 JWT 无效 |
| 403 | 40301 | 当前角色没有写权限 |
| 404 | 40401 | 物料、仓库、地块或库存资源不存在 |
| 409 | 40901 | 重名、状态冲突、删除引用冲突、幂等参数冲突或库存不足 |
| 500 | 50000 | 未预期数据库/服务异常；响应不包含 SQL 信息 |

## 十八、数据模型与约束

### 18.1 Material

```json
{
  "id": 1,
  "name": "番茄",
  "category": "作物",
  "unit": "kg",
  "spec": "一级果",
  "status": "ACTIVE",
  "createdAt": "2026-08-30T10:00:00Z",
  "updatedAt": "2026-08-30T10:00:00Z"
}
```

- `name`：必填，最多 128 字符，全表唯一。
- `category`：必填，最多 64 字符。
- `unit`：必填，最多 32 字符。
- `spec`：可空，最多 255 字符。
- `status`：`ACTIVE / DISABLED / DELETED`。
- `DELETED` 仅用于软删除，不允许客户端直接创建或更新为该状态。

### 18.2 Warehouse

```json
{
  "id": 1,
  "name": "一号成品仓",
  "location": "园区北侧",
  "status": "ACTIVE",
  "createdAt": "2026-08-30T10:00:00Z",
  "updatedAt": "2026-08-30T10:00:00Z"
}
```

- `name`：必填，最多 128 字符，全表唯一。
- `location`：可空，最多 255 字符。
- `status`：`ACTIVE / DISABLED / DELETED`。

### 18.3 Stock

```json
{
  "stockId": 1,
  "warehouseId": 1,
  "warehouseName": "一号成品仓",
  "materialId": 1,
  "materialName": "番茄",
  "unit": "kg",
  "totalQuantity": "500.125",
  "reservedQuantity": "300",
  "availableQuantity": "200.125"
}
```

- `(warehouse_id, material_id)` 有联合唯一索引。
- `quantity` 类型为 `DECIMAL(18,3)`，数据库约束 `quantity >= 0`。
- 库存只能通过库存业务方法变更，不能直接由 HTTP 更新。

### 18.4 StockRecord

```json
{
  "id": 10,
  "warehouseId": 1,
  "warehouseName": "一号成品仓",
  "materialId": 1,
  "materialName": "番茄",
  "unit": "kg",
  "type": "IN",
  "quantity": "500.125",
  "refType": "HARVEST",
  "refId": "harvest-20260830-001",
  "plotId": 3,
  "operatorId": 7,
  "remark": "上午采收",
  "createdAt": "2026-08-30T10:00:00Z",
  "updatedAt": "2026-08-30T10:00:00Z"
}
```

- `type`：`IN / OUT`。

- 流水创建后不可更新、不可删除。
- `plotId` 只在收获入库等有来源地块的业务中使用。

### 22.3 实际逻辑

Repository：

1. 查询 `stocks`。
2. 只保留状态有效且关联物料、仓库未删除的库存行。
3. 关联 `materials` 和 `warehouses` 获取展示字段。
4. 按 `warehouse_id ASC, material_id ASC` 稳定排序。

Service：

```text
stockRows = repository.listStocks(filter)
materialIds = distinct(stockRows.materialId)
reservedMap = reservationReader.reservedByMaterials(materialIds)

# 多仓按 warehouse_id 固定顺序分配虚拟占用
for row in stockRows:
    remainingReserved = reservedMap[row.materialId]
    row.reservedQuantity = min(remainingReserved, row.totalQuantity)
    reservedMap[row.materialId] -= row.reservedQuantity
    row.availableQuantity = row.totalQuantity - row.reservedQuantity
    if row.availableQuantity < 0:
        row.availableQuantity = 0

return stockRows
```

固定仓库顺序保证相同输入得到相同结果，同时满足聚合恒等式：

```text
Σavailable(material) = Σtotal(material) - reserved(material)
```

当前生产装配使用 `NoReservations`，所以订单模块接入前：

```text
reservedQuantity = 0
availableQuantity = totalQuantity
```

订单模块接入时应实现：

```go
type ReservationReader interface {
    ReservedByMaterials(context.Context, []uint64) (map[uint64]decimal.Decimal, error)
}
```

其 SQL 语义应为按物料聚合 `TRADING` 订单明细数量。

### 23.3 完整业务逻辑

```text
validate warehouseId/materialId/plotId/operatorId > 0
validate quantity > 0 and scale <= 3
validate Idempotency-Key present and length <= 128

BEGIN TRANSACTION
  existing = SELECT stock_records
             WHERE ref_type=HARVEST AND ref_id=Idempotency-Key
             ORDER BY id ASC LIMIT 1

  if existing found:
      if existing 的仓库/物料/地块/数量与本次请求不一致:
          ROLLBACK
          return 409
      stock = SELECT stock FOR UPDATE
      COMMIT
      return existing.id, stock.quantity

  material = SELECT material WHERE id=? AND status<>DELETED
  if material not found: ROLLBACK, return 404
  if material.status != ACTIVE: ROLLBACK, return 409

  warehouse = SELECT warehouse WHERE id=? AND status<>DELETED
  if warehouse not found: ROLLBACK, return 404
  if warehouse.status != ACTIVE: ROLLBACK, return 409

  if active plot does not exist:
      ROLLBACK, return 404

  stock = lockOrCreateStock(warehouseId, materialId)

  UPDATE stocks
  SET quantity = quantity + input.quantity
  WHERE id = stock.id

  INSERT stock_records(
      type=IN,
      quantity=input.quantity,
      ref_type=HARVEST,
      ref_id=Idempotency-Key,
      plot_id=input.plotId,
      operator_id=JWT.userId
  )

  INSERT outbox_events(
      aggregate_type=STOCK,
      aggregate_id=record.id,
      event_type=STOCK_INBOUND_CREATED,
      status=PENDING
  )
COMMIT

return record.id, oldStockQuantity + input.quantity
```

### 23.4 并发幂等处理

两个相同幂等请求可能同时在事务开始时查不到流水。数据库业务唯一索引负责最后兜底：

```text
request A: INSERT stock_record 成功，COMMIT
request B: INSERT stock_record 命中唯一索引，整个事务回滚
request B: 事务外重新读取已提交的原流水和库存
request B: 若请求参数完全一致，返回 A 的结果；否则返回 409
```

因此请求 B 在唯一索引竞争失败前执行的库存加法也会随事务回滚，不会多加库存。

### 23.5 库存行不存在时的并发初始化

```text
function lockOrCreateStock(warehouseId, materialId):
    stock = SELECT * FROM stocks
            WHERE warehouse_id=? AND material_id=?
            FOR UPDATE
    if found:
        return stock

    try:
        INSERT stocks(quantity=0, status=ACTIVE)
    catch duplicate key:
        # 另一个事务已创建同一联合唯一键，继续重新查询

    return SELECT * FROM stocks
           WHERE warehouse_id=? AND material_id=?
           FOR UPDATE
```

联合唯一索引保证最终只存在一条库存行，行锁保证并发累加不会丢失更新。

## 二十五、订单扣库内部能力

订单扣库当前是 Go Service 能力，不直接暴露独立 HTTP 接口。未来由交易 Service 在“确认成交”事务中调用。

### 25.1 输入

```go
type OutboundItem struct {
    WarehouseID uint64
    MaterialID  uint64
    Quantity    decimal.Decimal
}

DeductForOrder(
    ctx,
    orderNo,    // 流水 ref_id
    operatorID, // 当前管理员
    items,
)
```

`orderNo` 必填且最多 128 字符；每个数量必须大于 0 且最多 3 位小数。

### 25.2 独立事务调用

```text
function deductForOrder(orderNo, operatorId, items):
    for attempt in [1..3]:
        error = transaction:
            deductForOrderWithRepository(txRepository, ...)

        if success:
            return success
        if error is not MySQL deadlock(1213) or lock timeout(1205):
            return error
        wait 10ms * attempt

    return lastError
```

### 25.3 复用交易事务

交易 Service 已经持有事务时，应调用：

```go
warehouseService.DeductForOrderWithRepository(
    ctx,
    warehouseRepository.WithTx(tx),
    orderNo,
    operatorID,
    items,
)
```

这样订单状态、实际成交数量、库存和 OUT 流水可以在同一事务提交。事务重试应由最外层交易 Service 负责，避免只重试仓储子步骤。

### 25.4 扣库核心逻辑

```text
validate orderNo/operatorId/items
sortedItems = sort items by warehouseId ASC, materialId ASC

for item in sortedItems:
    stocks[item] = lockOrCreateStock(item.warehouseId, item.materialId)

# 必须先锁完所有行，再开始写
for item, stock in sortedItems, stocks:
    if stock.quantity < item.quantity:
        return INSUFFICIENT_STOCK  # 外层事务整体回滚

    affected = UPDATE stocks
               SET quantity = quantity - item.quantity
               WHERE id=stock.id AND quantity >= item.quantity
    if affected != 1:
        return INSUFFICIENT_STOCK

    INSERT stock_records(
        type=OUT,
        quantity=item.quantity,
        ref_type=ORDER,
        ref_id=orderNo,
        operator_id=operatorId
    )

return success
```

双重防超卖：

1. `SELECT ... FOR UPDATE` 串行化同一库存行的成交请求。
2. `UPDATE ... WHERE quantity >= ?` 保证即使前置判断出现竞争，数据库也不会扣成负数。

多物料任意一项失败时返回错误，由外层事务回滚之前已执行的所有扣减和 OUT 流水。

## 二十六、Outbox 事件

收获入库与库存、流水在同一事务写入：

```json
{
  "aggregateType": "STOCK",
  "aggregateId": "10",
  "eventType": "STOCK_INBOUND_CREATED",
  "status": "PENDING",
  "payload": {
    "recordId": 10,
    "warehouseId": 1,
    "materialId": 1,
    "materialName": "番茄",
    "quantity": "500.125",
    "unit": "kg",
    "plotId": 3,
    "operatorId": 7,
    "occurredAt": "2026-08-30T10:00:00Z"
  }
}
```

事务保证：

```text
库存成功 + 流水成功 + outbox 成功 => COMMIT
任意一步失败                         => ROLLBACK ALL
```

本阶段只保证事件可靠落库，不包含 Agent 消费端实现。

## 二十七、关键业务规则汇总

### 27.1 状态规则

| 资源状态 | 可查询 | 可入库 | 默认列表可见 |
|---|---:|---:|---:|
| `ACTIVE` | ✓ | ✓ | ✓ |
| `DISABLED` | ✓ | － | ✓ |
| `DELETED` | － | － | － |

### 27.2 删除规则

- 删除统一更新 `status=DELETED`。
- 物料存在非零有效库存时不能删除。
- 仓库存在非零有效库存时不能删除。
- 历史库存流水不删除。

### 27.3 数量规则

- 所有数据库数量：`DECIMAL(18,3)`。
- 所有 Go 业务数量：`decimal.Decimal`。
- 入库/出库数量必须大于 0。
- HTTP 接口不通过 `float64` 解析库存数量。
- 数据模型、DTO、流水和事件中没有价格、金额或成本字段。

### 27.4 幂等与不可变性

- 收获入库幂等键写入流水 `ref_id`。
- 相同幂等键和相同业务参数返回原结果。
- 相同幂等键但业务参数不同返回 409。
- 流水只创建，不提供更新或删除方法。

订单模块接入后，可售数量仍由仓储 Service 统一输出，HTTP 和前端不应自行重复计算。
